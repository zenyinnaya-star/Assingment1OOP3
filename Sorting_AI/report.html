Root Cause Analysis

In v1, 100% of failures (20/20) involved duplicate values. The Transformer's self-attention learned "which values are present" but struggled with "how many times each appears." The fix: generating 60% of training samples with deliberate duplicates, forcing the model to learn multiset (count-aware) behavior instead of set-like behavior.

Model Architecture

The model is a Transformer Encoder-Decoder that treats sorting as a sequence-to-sequence transduction problem. The unsorted array is fed to the encoder, and the decoder autoregressively generates the sorted array token by token.

INPUT [42, 7, 95, 3, 61] TARGET [3, 7, 42, 61, 95] | | v v +--------------------------------------------------+ | EMBEDDING LAYER (103 vocab -> 128d) | | + Positional Encoding (sinusoidal) | +--------------------------------------------------+ | | v v +------------------------+ +------------------------+ | ENCODER STACK x3 | | DECODER STACK x3 | | +------------------+ | | +------------------+ | | | Multi-Head Attn | | | | Masked MHA | | (causal mask) | | (4 heads, 128d) | | | | (4 heads, 128d) | | | +------------------+ | | +------------------+ | | | Feed-Forward | | | | Cross-Attention | | <-- attends to encoder | | (128 -> 512->128)| | | | (4 heads, 128d) | | | +------------------+ | | +------------------+ | | | Layer Norm + Res | | | | Feed-Forward | | | +------------------+ | | | (128 -> 512->128)| | +------------------------+ | +------------------+ | | | Layer Norm + Res | | +------------------------+ | v +------------------------+ | LINEAR (128 -> 103) | | Softmax -> logits | +------------------------+ | v OUTPUT: [3, 7, 42, 61, 95]

Key Design Choices

  • Vocabulary: 103 tokens (0-100 integer values + <SOS> + <EOS> + <PAD>)
  • Embedding dim: 128
  • Attention heads: 4
  • Encoder layers: 3
  • Decoder layers: 3
  • Feed-forward dim: 512
  • Dropout: 0.1
  • Position encoding: Sinusoidal (fixed)
  • Weight init: Xavier uniform
  • Gradient clipping: max_norm=1.0

Why a Transformer?

Sorting is a permutation problem — every output element depends on the global ordering of all input elements. The self-attention mechanism in Transformers naturally captures these global dependencies, making it ideal for learning sorting. Unlike RNNs, Transformers process all positions in parallel, enabling efficient GPU utilization.

Generation Parameters

  • Array length: Random between 3 and 10 elements
  • Value range: Integers from 0 to 100
  • Target: The same array sorted in ascending order
  • Duplicate generation (v2): 60% of training samples are generated by choosing fewer unique values than the array length, guaranteeing repeated numbers
  • Padding: Variable-length sequences padded with <PAD> token within each batch

Tokenization Scheme

Token 0-100 → Integer values 0-100 Token 101 → <SOS> (Start of sequence - decoder input prefix) Token 102 → <EOS> (End of sequence - signals generation is complete) Token 103 → <PAD> (Padding - ignored in loss computation)

Training Pipeline

  • Batch size: 256
  • Optimizer: AdamW (lr=1e-4, weight_decay=1e-4)
  • Scheduler: Cosine Annealing LR (eta_min=1e-6)
  • Loss: Cross-Entropy (ignoring PAD tokens)
  • Teacher forcing: 100% during training (ground truth shifted right as decoder input)

Development Steps

Step 1: Environment Setup

Verified NVIDIA RTX 3050 Laptop GPU with CUDA 13.2 (driver 595.71.05). Installed PyTorch 2.12.0+cu132, matplotlib 3.10.9, and tqdm. GPU has 6GB VRAM — sufficient for a ~1.4M parameter Transformer.

Success

Step 2: Dataset Design (v1)

Created a synthetic dataset of 95,000 random integer arrays. Each sample: random-length array (3-10 elements) with values 0-100. The target is the sorted version. Used a collate function with dynamic padding per batch.

Success

Step 3: Model Architecture

Designed a Transformer Encoder-Decoder with sinusoidal positional encoding. The model uses tokenized integer values (vocab_size=103), 4-head attention, 3 encoder/decoder layers, and Xavier initialization. Total: 1,415,784 parameters.

Success

Step 4: Training Pipeline

Built the full training loop with: AdamW optimizer, cosine annealing LR scheduler, gradient clipping (max_norm=1.0), causal masking, cross-entropy loss with PAD token masking, and three metrics (loss, token accuracy, exact match).

Success

Step 5: Bug — Wrong PyTorch API Attribute

First run crashed with: AttributeError: 'total_mem'. Did you mean: 'total_memory'?

Fix: Changed total_mem to total_memory. PyTorch 2.12 uses total_memory.

Bug Fixed

Step 6: Timeout on First Full Run

50-epoch config exceeded runtime timeout. Model already at 97%+ accuracy by epoch 1.

Fix: Reduced to 25 epochs. Still converged fully.

Config Adjusted

Step 7: v1 Training Complete

Training completed in 26.6 minutes. Results: 99.86% token accuracy, 98.97% exact match on test. Excellent overall, but not perfect.

Success

Step 8: Failure Analysis — Duplicate Bug

Analyzed all 23 failures out of 2,000 test samples. 100% of failures (23/23) involved duplicate values. The model was dropping repeated numbers — treating the array as a set instead of a multiset. Length-10 arrays were most affected (11/23 failures).

Example: Input [60, 95, 17, 95, 67] → expected [17, 60, 67, 95, 95] → got [17, 60, 67, 95] (dropped one 95)

Root Cause Found

Step 9: Dataset Redesign (v2)

Modified the dataset generator to produce 60% of training samples with deliberate duplicate values. The generator picks fewer unique values than the array length, guaranteeing repetitions. Validation set: 50% duplicates. Test set: natural distribution (no bias).

Improvement

Step 10: v2 Training & Results

Retrained from scratch with 100k samples (v2 dataset), 20 epochs, 19 minutes. Results: 99.99% token accuracy, 99.92% exact match on test. Duplicate handling improved from ~94% to 99.14%. Only 3 failures out of 2,000 test samples.

Major Improvement

Failures & Lessons Learned

Bug 1: Wrong PyTorch API attribute

AttributeError: 'torch._C._CudaDeviceProperties' object has no attribute 'total_mem' Did you mean: 'total_memory'?

The PyTorch CUDA device properties API uses total_memory, not total_mem. Lesson: always check the exact attribute names for your PyTorch version.

Issue 2: Training timeout

The initial 50-epoch configuration was too long. The fix was straightforward: reducing epochs, since the model converges fast (97%+ accuracy by epoch 1).

Issue 3: Duplicate value blindness (v1)

The most significant finding. The Transformer's self-attention learned "which values are present" but not "how many times each appears." This is a fundamental challenge with autoregressive generation — the decoder must count and re-emit identical tokens.

v1 Failure example: Input: [60, 95, 17, 95, 67] Expected: [17, 60, 67, 95, 95] Got: [17, 60, 67, 95] <-- dropped one 95

Fix: Data augmentation — flooding the training set with duplicate-heavy samples forced the model to learn multiset behavior. Accuracy on duplicate arrays jumped from ~94% to 99.14%.

Remaining ~0.08% Error (v2)

Only 3 out of 2,000 test samples fail in v2, all involving duplicates in longer arrays (length 9-10). These are edge cases where the model occasionally miscounts triples (3 copies of the same value) or swaps adjacent values.
